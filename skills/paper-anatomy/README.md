# paper-anatomy｜把论文放上证据解剖台

简体中文 · [English](README_EN.md)

> **一句话定位：** 面向所有读者、专长是实验与行为研究，像做一场不伤论文的“学术解剖”，沿着研究故事、理论、变量、参与者体验、数据与讨论逐层查清证据；主要任务是读懂、审查和核验论文，不负责把研究落地为程序或复现包。

## 什么时候该把论文送上“解剖台”

当普通摘要已经不能回答你的问题时，可以使用 `paper-anatomy`。它特别适合：

- **读懂完整研究故事**：重建引言如何提出问题、文献综述如何推出缺口、多个 Study 如何共同支撑结论，以及讨论如何把证据放回理论。
- **辨清变量与测量**：说明自变量、因变量、中介、调节和控制变量如何操作化，原始反应怎样变成最终指标。
- **从被试视角重走研究**：还原参与者实际看见什么、理解什么、做出什么反应，并检查操纵、任务难度、需求特征和替代解释。
- **审查统计证据与结论**：把模型、比较和图表逐项映射到假设，区分“结果显著”“支持某个命题”和“可以推广到更大范围”。
- **适配不同研究类型**：实验、问卷、纵向、定性、理论论文、系统综述、Meta-analysis、文献计量、Delphi、共识与指南都会进入不同的证据路线。
- **核验网络科普或媒体主张**：把博主、新闻或社交媒体的具体说法与其引用论文对照，判断一致、部分一致、过度概括、不受支持或暂时无法判断。
- **了解论文后续位置**：在需要时检索代表性的复现、综述、方法改进、反证和边界条件，避免把旧论文当成领域最后结论。

## 工作方式：从研究故事走到证据边界

`paper-anatomy` 不用同一套摘要模板处理所有论文，而是先判断研究类型，再选择对应路线：

1. 确认论文版本、正文、补充材料和用户真正想解决的问题。
2. 对 PDF 生成独立来源清单，记录文件页码、章节、图、表、图片及实际读取的材料范围。
3. 判断主要文献类型；实验、问卷、纵向、定性、理论、综述、Meta、文献计量和共识研究不会被强行写成同一种流程。
4. 重建“已有研究 → 缺口或争议 → 理论解释 → 假设/命题”，检查引言是否讲清研究为什么成立。
5. 还原每个 Study 或证据生产阶段，连接参与者/资料、测量、变量、数据处理、模型与结果。
6. 建立“统计证据 → 支持的命题 → 不能推出的结论”映射，不用显著性替代理论判断。
7. 检查讨论怎样闭合研究故事，区分作者解释、实际贡献、推广边界和替代解释；矛盾内容保留双方定位。
8. 按需核验传播主张或检索后续证据，最后交付带紧凑来源指针的 ABC 解剖报告。

## 可以这样向它下“解剖单”

```text
$paper-anatomy 请解剖这篇多 Study 论文，重点说明引言怎样推出研究问题、
每个 Study 排除了什么替代解释，以及最终讨论是否超出了数据证据。
```

```text
$paper-anatomy 请从被试视角重走这项社会排斥实验：参与者看见了什么、
他们是否知道其他玩家是真人，以及操纵是否同时改变了任务难度或需求特征。
```

```text
$paper-anatomy 请分析这篇纵向问卷研究，检查波次、样本流失、变量测量、
滞后模型和因果措辞，不要把它改写成实验流程。
```

```text
$paper-anatomy 某博主引用这篇论文声称“这种运动对所有成年人都有效”。
请比较博主原话与论文的样本、设计、效应大小和结论边界，并给出判断。
```

## 开始解剖前，请尽量提供

| 信息 | 最低要求 | 提供后会更好 |
|---|---|---|
| 论文 | PDF、DOI、网页链接或可读取的正文之一 | 正式发表版本及准确题名 |
| 附加材料 | 没有也可以开始，但会明确证据缺口 | Supplement、附录、开放数据、预注册或材料仓库 |
| 你的关注点 | 可以只说“帮我读懂” | 指定理论、变量、某个 Study、图表、统计模型或争议 |
| 使用目的 | 可不提供 | 开题、综述、汇报、实验学习、研究构思或科普核验 |
| 待核验主张 | 仅核验任务需要 | 博主原话、上下文、原链接及其引用论文 |
| 输出偏好 | 默认中文 | 篇幅、表格深度、是否解释统计、是否保存为 Markdown |

材料不完整时仍可工作，但会把内容标为 `原文明确`、`补充材料`、`外部文献`、`合理推断` 或 `未能核实`，不会用猜测补齐缺失事实。

## 你会拿到怎样的“解剖报告”

默认交付采用 ABC 结构：

| 部分 | 回答的核心问题 | 主要内容 |
|---|---|---|
| **A. 研究叙事与理论定位** | 这篇论文为什么要做、想讲清什么？ | 研究问题、理论源头、概念边界、综述逻辑、假设和跨 Study 架构 |
| **B. 研究设计、测量与证据** | 证据究竟怎样产生？ | 被试/资料流程、操纵与测量、变量角色、数据处理、统计方法及结果—结论映射 |
| **C. 结论、讨论与领域位置** | 论文真正增加了什么，又能说到哪里？ | 数据—讨论闭环、理论/方法/实证贡献、限制、所有论文必做的 C4 领域锚定，以及校准后的剩余问题 |

当提供 PDF 时，Skill 会先建立两层索引：先区分单篇论文与会议集/论文集中的各篇论文，再为每篇定位**摘要、前言与理论、研究设计、结果与数据处理、讨论与文章价值**。用户指定文章时按序号、DOI 或唯一标题短语精确选择；未指定时默认阅读全部论文。B4、C1 和最终判断会用 `[Paper: PDF p. 7, Fig. 2]` 一类短指针定位结论。完整索引单独保存在 `source_bundle.json`，不会挤压 ABC 主报告；若只有摘要，则明确标为 `source-limited`，不猜页码。

报告不会只复述段落，而会尽量形成几条可以检查的链条：

```text
已有研究 → 缺口或争议 → 理论解释 → 可检验预测
参与者经历 → 原始反应 → 指标 → 统计模型 → 结论
观察结果 → 作者解释 → 理论推进 → 推广边界
```

## 运行和依赖：轻量启动，按任务扩展

- Skill 本身不要求 API key、MCP 服务或专用本地配置。
- 需要能够读取用户提供的论文正文；只有摘要或网页片段时仍可分析，但会明确材料边界。
- C4 当代近况检查适用于所有论文：近三年论文使用 3–5 篇精简的领域锚点，较旧论文默认约 5 篇以上进展、复制、修正或争议证据；每条均提供可点击学术链接。完成这一部分需要 Agent 具备联网检索能力；确实无法联网时会保留 C4 并明确检索受限，而不会把它省略或写成当前定论。
- 生成 PDF 来源清单需要 Python 3 与 `pypdf`；安装 `pdfplumber` 后可获得图表标题和图片坐标，使用 `--render-pages` 时还需要 `pdftoppm`。
- 仓库包含一份程序生成、无真实论文或被试数据的合成 PDF fixture，并在 CI 中实际测试页码、章节、Figure/Table、DOI、链接、图片和 `--no-text` 输出。
- Markdown 结构与定位校验脚本只使用 Python 标准库。
- Skill 不依赖 R、PsychoPy、E-Prime 或其他实验平台，因为它不负责实现实验程序。

## 这把“手术刀”停在哪里

- 不生成实验程序、平台工程、完整刺激材料、试次日志或可执行复现包。
- 不把相关关系改写成因果关系，也不把统计显著直接等同于效果重要。
- 不虚构样本、量表、统计值、链接、作者观点或未提供的补充材料。
- 不因为一篇论文讲得流畅，就默认其证据足够；也不因为存在限制，就否定全部研究价值。
- 核验科普时只判断主张与证据是否一致，不推断传播者的动机。
- 医学、健康和其他高风险主题中，它不能代替诊断、临床指南或领域专业意见。
- 如果目标已经变成搭建、迁移或复现实验，应进入 `paper-reconstruction`。

## 与 paper-reconstruction 的关系：双臂如何接力

`paper-anatomy` 是这台“论文手术机器人”的解剖臂，负责查清论文内部的理论、证据与边界；[`paper-reconstruction`](../paper-reconstruction/README.md) 是重组臂，负责把已经查清的研究重新连接为流程、材料、程序、数据和分析。

- **只想读懂、评议或核验论文**：使用 `paper-anatomy`。
- **准备搭建、复现、迁移或改造研究**：使用 `paper-reconstruction`。
- **两者都需要**：由 `paper-reconstruction` 统领交付，并先完成实现所需的最小论文解剖。

运行规则与完整字段分别见 [`SKILL.md`](SKILL.md) 和 [`references/output-contract.md`](references/output-contract.md)。项目总览见 [`paper-to-paradigm`](../../README.md)。
