## D3. 复现验证与差异处理

| 验证对象 | 测试方法 | 通过标准 | 未通过时处理 |
|---|---|---|---|

正文、Supplement、OSF、预注册、数据或代码存在冲突时，必须增加版本差异与消解测试；不能静默覆盖某一版本。统计复现应保留“导入 → 检查 → 排除 → 派生 → 描述 → 原文模型 → 对比 → 表图 → 导出 → 运行记录”的证据链，但分析模型本身在 C5 说明。

结构化复现包必须运行：

```bash
python scripts/audit_replication_bundle.py BUNDLE_DIRECTORY
```

E-Prime 只有在 `.es3`、`.ebs3`、固定版本烟雾测试、日志核对和 SHA-256 都存在时才能标记为 `runtime-verified`。
第一份 `runtime-verified` 案例还必须对应一篇明确论文，并记录 DOI、可合法使用的 Supplement/OSF/材料、实现差异与论文到程序的对应关系；中性 starter 不算论文复现案例。
